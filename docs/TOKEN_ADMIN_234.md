# Dhan daily token update 2.3.4

Supersedes TOKEN_ADMIN_233.md. Google OAuth setup and Google Client ID are no longer used. The permanent Dhan Client ID is unchanged. Public trading/research screens stay keyless; only credential changes require a separate token-admin password. The UI has password fields for the permanent admin password and daily Dhan token, Show/Hide for the token, Unlock/Lock, and Save & check. Both entered values are transient; no local storage. Dhan candidate is still verified against the fixed Client ID using the profile API before saving. No broker execution.

Run deploy/configure-token-admin.sh once, then deploy/release-existing.sh from live-app. Configuration resolves the existing Dhan secret and preserves the fixed Client ID. Terminal prompts for a chosen admin password twice (12+ printable ASCII characters). The password is never printed or sent to git; only a random-salt PBKDF2-SHA256 hash (600000 rounds) is stored in Secret Manager and attached to the runtime. Daily token updates grant version-adder and accessor only on the existing Dhan token secret to the existing runtime account. The admin hash secret receives accessor only. Trading APIs remain public as explicitly requested earlier; this password protects only token administration. There is no distributed brute-force limiter, so use a strong unique admin password and HTTPS.

Validation: 26 tests pass. Earlier Google-verifier tests are replaced with admin-password tests; this is not a cumulative test count. Tests cover bad/missing passwords, malformed hashes, successful unlock, check-before-save, wrong Client ID, Dhan rejection, no token reflection, and original live/replay/rollout regressions.
