# Theta Plus — pre-implementation code audit
Date: 2026-10-18
Repository: signatureproprt-boop/Theta-plus
Scope: user-confirmed Theta-pluse-main.zip (September 16 archive), not deployed infrastructure.
Decision: NO-GO for live order execution or claims of validated option-strategy performance. Useful research scaffolding exists, but correctness defects must precede new analyst features.

## Verification performed
- Inspected backend startup, data models/mapping/normalization, runtime pipeline, PCR/OI/VWAP/scoring, replay/outcomes, snapshot storage, research/parity/OOS, paper execution, live execution/risk/reconciliation, Sheets settings/reporting, frontend routes/API/chart and build configuration.
- Final baseline: 350 passed, 1 failed, 1 skipped (352 tests). Failure: tests/test_phase_j_validation.py::test_env_example_holds_placeholders_only. backend/.env.example is absent in the original archive as well as the restored source.
- Initially missing audit-environment dependencies were installed separately. A temporary /app/backend symlink satisfied hardcoded test paths; local server and dummy Mongo connection configuration supported tests. No real Mongo database, broker or market credentials were used. Database persistence is NOT verified.
- Final suite ran with a local server on port 8001 because one test hardcodes localhost:8001/openapi.json despite BACKEND_URL configuration. Earlier connection/dependency failures were environment/harness issues, not counted as product defects.
- Frontend: npm install --ignore-scripts, npm run build, npm run lint succeeded. No browser visual/E2E verification; supplied tests/e2e directory has no substantive tests.
- Focused isolated reproductions below used synthetic fixtures and a mock broker, never real orders.
- No strategy changes, deployments or live arming performed for this audit.

## Existing strengths
Pure calculation/rule modules, frozen Pydantic models, explicit reason codes, score shown separately from probability, default RESEARCH mode, dual live enable/arm switches, broker adapter separation, synthetic-data warnings, first-write-wins SQLite snapshot utility, chronological replay and unit coverage are useful foundations.
Passing current tests does not validate actual market performance or missing failure scenarios.

## Confirmed findings

### A01 — Critical when LIVE enabled: position limit not enforced from fills
Evidence: backend/execution/service.py _apply_broker_state updates OrderRecord but never updates risk_state.open_positions. RiskState starts at zero. Pipeline does not periodically reconcile positions or invoke refresh_order.
Reproduction: existing mock helpers, max_open_positions=1, max_trades_per_day=10, two different valid signal IDs -> both approved; open_positions counter remains 0.
Impact: live-enabled deployment can exceed configured position limits.
Required fix: broker-confirmed, persisted position accounting and pending-order exposure reservation; fresh reconciliation, concurrency-safe entry gates. Add regression test using actual fill lifecycle, not manually assigning counters.

### A02 — High: feed outage retains old actionable display state
Evidence: Pipeline.tick catches feed exception and immediately returns dashboard without recomputing freshness or replacing decision; dashboard renders stored features/checks; chart router also reads stored decision.
Reproduction: seed strong CE fixture, then make feed fail ten minutes later -> decision CE_SETUP and health OK remain.
Impact: stale actionable setup remains displayed. Early return does prevent a new submission on that failed tick, so this finding is not a claim that the outage itself sends orders.
Fix: explicit data-blocked state, current-time freshness on read/tick failure, stale status across dashboard/chart/paper.

### A03 — High: live VWAP input is not a valid minute-candle series
Evidence: DhanFeed maps index market-quote OHLC/volume into one Bar at the first quote per minute; later quotes do not update that minute. It does not build trade-volume deltas or use futures candles. compute_vwap substitutes an unweighted mean when total volume <= 0 and marks it valid.
Reproduction: zero-volume Bar(high=110,low=90,close=100,volume=0) -> VWAP 100 rather than unavailable.
Impact: a 25-point score component can use a non-VWAP value. Broker-field semantics still need live verification, but absence of proper candle aggregation is directly visible.
Fix: explicit futures source and complete causal OHLCV bars, session warmup, zero-volume unavailable status.

### A04 — High: parity harness does not exercise actual runtime feed/bar lifecycle
Evidence: research/parity.py live_path_signals reconstructs its own bars/session resets, closely mirroring replay. Actual DhanFeed keeps first quote per minute; replay appends every snapshot; Pipeline PCR history/memory/prev_snapshot are not reset per session, whereas replay resets them.
Impact: PASS from the existing parity harness cannot prove production live/replay equivalence.
Fix: replay the real Pipeline with an injected clock/feed and shared session/candle builder; test repeated ticks and cross-session rollover.

### A05 — High: replay mixes option contracts and sessions
Evidence: observations_from_snapshots filters only timestamp, strike and side; no underlying/expiry/session constraint. ReplaySignal/PaperPosition do not carry full selected contract identity.
Reproduction: a next-day snapshot with another expiry at the same strike is accepted as one future observation.
Impact: target/stop and P&L may use another contract/day.
Fix: immutable contract key, session deadline and expiry-specific observations/invalidations.

### A06 — High when LIVE enabled: contract resolution can choose an old/wrong expiry
Evidence: ExecutionService._resolve calls InstrumentMap.resolve without expiry; resolve returns first strike/side match. validate_instrument does not reject expired contracts.
Reproduction: old and new contracts sharing strike/side -> default resolve selects 2020 expiry when it appears first.
Fix: carry chain expiry/security identity end-to-end, exact mandatory expiry match and as-of tradability check.

### A07 — High: runtime order/risk/paper state is not durable
Evidence: orders dict, RiskState and paper positions exist only in memory; comment “Persist the idempotency key” refers to dict insertion. Daily counters have no session-date reset. record_realized_pnl exists but no runtime caller was found.
Impact: restart loses dedupe/risk/journal history; long-running session counters may span days; realised-loss lock is not connected to a complete broker P&L lifecycle.
Fix: durable journal, recovery/reconciliation, exchange-session counters, confirmed fill/P&L accounting.

### A08 — High when LIVE enabled: complete automated exit lifecycle absent
Evidence: Pipeline invokes attempt_entry. can_exit checks whether exit is allowed but does not submit protective exits. No periodic broker refresh/exit loop connects stop/target/invalidation to a position exit.
Impact: enabling entry infrastructure is not a managed trading system.
Fix: keep LIVE disabled until protective exits, partial fills, cancellation, kill-switch and recovery are specified/tested. New research integration must not activate LIVE.

### A09 — High: replay and paper execution assumptions diverge
Evidence: replay evaluate_outcome exits at configured target/stop price after an LTP jump; paper update closes at observed LTP. Both enter from signal-time LTP without executable bid/ask/latency/depth. Missing quote fields prevent realistic fills.
Impact: replay/paper P&L disagreement and optimistic fills.
Fix: one shared execution policy, bid/ask/latency and gap-aware exits; candle/LTP-only studies explicitly approximate.

### A10 — High: expiry and quote provenance/fields incomplete
Evidence: OptionQuote has no bid/ask, quote timestamp, depth or security ID. Mapper _leg drops Greeks and bid/ask fields; security_id returned by mapper is dropped by normalization. map_option_chain timestamps data with local now; invalid index quote timestamps fall back to now.
Reproduction: invalid quote time string becomes supplied current time.
Impact: missing exchange-time data can look fresh; spread checks and contract-level validation impossible.
Fix: preserve raw payload, received/exchange timestamps, unknown freshness and full contract/quote metadata; do not fabricate exchange time.

### A11 — Medium: epoch timestamp parsing depends on host timezone
Evidence: parse_timestamp uses naive datetime.fromtimestamp then interprets that value as IST.
Reproduction: epoch 0 did not normalize to 1970-01-01T05:30:00+05:30 in the audit environment.
Fix: convert epoch using an explicit UTC-aware datetime and test under several host TZ settings.

### A12 — High research integrity: incomplete dataset fingerprint
Evidence: snapshot_fingerprint omits expiry, OHLC other than close, timestamps of tick/chain, volume/IV/Greeks on option legs and other relevant fields.
Reproduction: changing only chain expiry leaves fingerprint unchanged.
Impact: different research inputs can share dataset identity.
Fix: canonical hash of complete versioned decision/execution inputs, plus config/code and provenance manifests.

### A13 — Medium: live data does not automatically reach SQLite replay store
Evidence: SnapshotStore utility exists, but Pipeline.tick has no save call; it queues Sheets only.
Impact: selecting SQLite replay will not inherently replay the live runtime history. External ingestion may populate data, but was not supplied/verified.
Fix: explicit append-only capture stage with failure/retention/backpressure policy and source timestamps.

### A14 — Medium: expiry/session rollover and lookback semantics incomplete
Evidence: DhanFeed._expiry is cached indefinitely; client expiry list cached. Runtime PCR/ATM history, previous snapshot and SignalMemory lack daily reset. PCR lookback is sample count rather than fixed elapsed time; polling changes alter horizon.
Fix: session/expiry lifecycle, time-based windows, same-contract OI comparisons, warmup after rollover.

### A15 — Medium: current strategy differs from proposed trend-first system
Evidence: weighted PCR/VWAP/OI score; minimum score 70; price confirmation weight 10; OI weight totals 55. Rules infer put-writer support from Put OI dominance. No hard regime -> opportunity -> contract sequence, multi-timeframe pivot trend model or pullback-continuation gate.
Impact: current score can qualify without the planned price structure. OI interpretation is a strategy hypothesis, not proof of writing.
Fix: preserve current strategy as baseline, add separately versioned research model only after foundational fixes.

### A16 — Medium: multi-expiry/institutional/breadth/event layers absent from runtime
Evidence: DhanFeed fetches nearest expiry only; no runtime combined/expiry-wise PCR engine, point-in-time constituent breadth or FII/DII/event calendar pipeline found. Time filter uses wall-clock only, not trading-day/holiday/event eligibility.
Fix: feed audit before feature claims; exact expiry-calendar verification and coverage-labelled optional modules.

### A17 — Medium security/operations: application has no authentication boundary
Evidence: server registers research/config/execution-log routes without auth dependencies; frontend has only / and /chart. session.ts mentions cookies/logout but backend auth routes do not exist. Research POST accepts local filesystem path and synchronous heavy computation; no request workload limits or path allowlist found.
Impact if publicly exposed: research/order logs may be readable, arbitrary supported local dataset paths may be processed, expensive requests can block service. Deployment-level protection was not inspected. No UI/API live-arm endpoint found.
Fix: authenticated roles, configured dataset IDs/allowlist, bounded jobs/rate limits, explicit production CORS policy.

### A18 — Medium: settings propagate inconsistently
Evidence: _pull_sheet_settings replaces Pipeline.config, but paper and execution/risk services retain original config objects; routes often call cached get_config instead. Adjustable target/stop/cooldown values may therefore differ across views/components.
Fix: single versioned configuration snapshot propagated atomically, with active-position rules preserved explicitly.

### A19 — Medium: UI/data origin can be misleading
Evidence: chart router LIVE_NOTE and paper origin labels hardcode simulated feed even when DhanFeed selected. build_feed silently falls back to sim when data_source=dhan but credentials missing (dashboard does show actual feed name).
Fix: explicit unavailable data state for requested real feed; origin derived consistently from actual source and carried through journal/chart.

### A20 — Low/medium: portability and release packaging gaps
Evidence: original archive lacks .env.example required by its own test; tests hardcode /app and localhost:8001; backend requires MONGO_URL/DB_NAME on import; original repository stores ZIP rather than normal source. Frontend package installation/build succeeded in audit environment, but exact full backend requirements file was not installed as a deployment lock. No substantive browser E2E tests provided.
Fix: portable test fixtures, placeholder env template, clean source checkout, pinned reproducible dependencies and CI; browser smoke tests before release.
